# CognitiveDynamics EzLLMRouter JavaScript and TypeScript client

Package version **0.3.0** uses the CognitiveDynamics name. Existing wire and
accounting contracts remain compatible. Historical release numbers below
describe when each capability was introduced.

## TypeScript and module formats

The same package supports CommonJS `require` and native ESM imports. TypeScript
declarations ship in the package and require no separate `@types` dependency:

```ts
import {EzLLMRouterClient, IntegrationClient} from "@cognitivedynamics/ezllmrouter-client";
import type {Wire03, IntegrationV3} from "@cognitivedynamics/ezllmrouter-client";

const client = new EzLLMRouterClient({baseUrl: origin, token});
const capabilities = await client.getCapabilities();
const accounting = new IntegrationClient(origin, ingestToken, {version: "3"});
```

The `Wire02`, `Wire03`, `IntegrationV1`, `IntegrationV2` and `IntegrationV3`
type namespaces mirror the adopted payload schemas. `IntegrationClient` infers
the selected version; methods and event arguments are checked against that
version. Execution errors retain the runtime's snake_case recovery properties;
accounting errors expose `http_status` and `retry_guidance` too. The existing
`httpStatus` and `retryGuidance` getters remain available.

The payload declarations are generated by `generate_types.py`; the API surface
is declared in `index.d.cts`. To regenerate after an authorized contract change,
use the locked Python environment. Static types do not enforce numeric ranges,
date validity or cross-record semantics; runtime validation still applies.
TypeScript 5.9.3 consumer checks exercise both NodeNext and CommonJS resolution
against a locally packed package. Run `bash tests/client_languages/check_typescript.sh`
with that compiler installed; `--package-only` checks exports and declaration
syntax without claiming a compiler type check.

## Response validation and recovery

Wire 0.2 execution and attribution responses have a 1 MiB byte limit. Wire 0.3
embedding/rerank and external accounting responses have a 16 MiB limit. Native
fetch responses are read incrementally; the client rejects non-identity content
encoding, invalid or excessive declared lengths and length mismatches. A failed
read cancels the stream and releases its reader. Requests are never replayed.

All protocols use strict UTF-8 JSON decoding, rejecting duplicate keys, unsafe
or non-integer JSON numbers, NUL, lone surrogates and nesting beyond 32 levels.
Escaped newlines and tabs remain valid in free text; field-specific schema
restrictions still apply. Embedding and rerank results are checked against the
submitted profile, dimensions and item identities, so newly registered
configurations do not require client fixture changes.

Execution errors expose a recovery handle only when it is structurally valid
and matches the original submission ID or work selector. A mismatched response
cannot substitute another work identity. Valid matching handles remain available
for query-first recovery after a failed result.

An injected `fetchImpl` must return a response with a readable byte stream or
`arrayBuffer()`. Buffered injected transports own their allocation; the client
checks their bytes before decoding. JSON-only response doubles are unsupported.
Both clients default to a **35,000 ms total deadline** for each HTTP exchange,
including response-body consumption. Configure `timeoutMs` in either constructor;
use a positive integer or explicitly set `null` to disable the total budget.
The client passes an `AbortSignal` to `fetchImpl`, cancels an active reader on
expiry and reports `TRANSPORT_OUTCOME_UNKNOWN` / `query_first` without replaying.
A custom transport should honor that signal to stop its underlying I/O; the client
still bounds its own wait if the injected function does not settle.

Request serialization happens before transport work. Circular structures, BigInt,
non-integer numbers, unsupported objects and invalid Unicode give `SCHEMA_INVALID`
with `never` recovery and zero requests sent. Wire 0.2 also rejects null request
values, matching the Python client. Wire 0.3 rejects C0/DEL controls in all typed
strings; wire 0.2 result text retains escaped newlines and tabs.

Bearer credentials and injected fetch implementations are private fields. Decoded
response schema/correspondence violations use `PROTOCOL_INVALID`; unreadable or
malformed replies retain `TRANSPORT_OUTCOME_UNKNOWN`. A valid server error retains
its server code. Accounting retry guidance is checked against the supported enum;
missing or invalid guidance on 5xx responses defaults to `query_first`.

## External accounting integration (0.2.3)

Node `>=24.22.1 <25` is supported, matching the inspected Vega platform Node 24
declaration. The [v2 contract](../../docs/API.md#external-accounting-v2)
and [examples](../../tests/fixtures/contracts/integration-readiness-v2/examples.json) define
the successor event shapes. Install the private `0.3.0` tarball locally. No hosted
registry or provider SDK is needed.

Configure `baseUrl` from a trusted service origin, never from a model result or
other untrusted input. The client accepts only an HTTP(S) origin without a path,
credentials, query or fragment. It requests `Accept-Encoding: identity`; the
EzLLMRouter service and any trusted proxy must not send Brotli-compressed responses.
Node's built-in `fetch` can decode a response before application code sees it,
so this header alone is not a defense against an untrusted server. Keep the
selected runtime at or above the fixed Node 24.22.1 patch level.

Provide your trusted service `origin`, ingest credential, dataset/account/model
IDs, complete `event` and `featureSnapshot` records. CI extracts and executes
this example against a disposable service with synthetic records.

<!-- executable-example: javascript-accounting-v2 -->
```js
const {IntegrationClient} = require("@cognitivedynamics/ezllmrouter-client");
const client = new IntegrationClient(origin, ingestToken, {version:"2"});
const eligibility = await client.eligibility(datasetId, accountId, modelId);
const receipt = await client.submitObservation(event); // one HTTP delivery, no model call
const recovered = await client.recoverReceipt(datasetId, event.event_id);
const stored = await client.submitSnapshot(featureSnapshot);
const snapshot = await client.snapshot(datasetId, featureSnapshot.snapshot_id);
```

`createDataset`, `registerAccount`, `setAccountState` and `report` are
available to an appropriately authenticated owner administrator. A normal
ingest credential can submit observations and read its receipts/eligibility;
it cannot administer accounts or read reports. The client never retries a
request automatically. If delivery has an unknown transport outcome, read the
receipt first and then redeliver the **same** event ID/body only if absent.
An actual model retry requires a distinct attempt ID and belongs to the
platform executor, not this transport client.
V2 owner/report principals can call `exportDataset(datasetId)`; the service
returns included events, selected action and referenced eligibility/snapshot
evidence. Construct with `{version:"1"}` or omit the option to use the preserved
v1 route and event schema against the new service. Real captured features
require owner policy adoption; the default release accepts synthetic low-class
snapshots only.

In the corrected v2 service, `report(datasetId)` returns `usage_state` separately
from `cost_status`. It also returns a server `eligibility_assessment` separately
from the caller's `eligibility_evidence_status`. A same-second ordering tie is
`indeterminate`; it is not proof of a verified selection. Snapshot and lineage
`binding_conflict` labels preserve older inconsistent observations without
claiming their references are valid. `exportDataset(datasetId)` includes
`eligibility_assessments` and `snapshot_reference_assessments` beside immutable
events. The client returns these fields without changing or retrying the work.

Version 0.0.3 adds versioned attribution-run and outcome operations while
retaining the strict wire-0.2 submission body. The client talks only to the
EzLLMRouter service. It does not call a provider directly.

```js
const { EzLLMRouterClient } = require("@cognitivedynamics/ezllmrouter-client");
const client = new EzLLMRouterClient({ baseUrl: "http://service:8765", token });
const run = await client.startRun({
  version: "1", run_id: "run.example.1", task_id: request.task_id,
  task_class: request.task_class, evaluation_ref: "rubric.example.v1",
  mode: "user_delegated_agent", agent_id: "agent.registered",
  agent_version: "v1", initiating_user_id: "user.authorized",
});
const reply = await client.submitInRun(request, run.run_id, { wait_ms: 3000 });

const child = await client.startRun({
  version: "1", run_id: "run.example.child", task_id: request.task_id,
  task_class: request.task_class, evaluation_ref: "rubric.example.v1",
  mode: "nested_agent", agent_id: "agent.child", agent_version: "v1",
  parent_run_id: run.run_id,
});
```

Use `direct_human` with a human credential and no agent fields. Use
`autonomous_agent` with a registered agent/version and no initiating user.
Runs do not grant access by themselves; the server checks caller, delegation,
owner and model permission before each send.

An explicitly authorized evaluator uses `reportOutcome(event)` for a versioned
task or step verdict. `getOutcomeReceipt(eventId)` recovers a lost receipt
without writing or sending again. Repeated identical events return the same
receipt; a changed event with the same ID conflicts.

## Speech-operation eligibility (integration v3)

Release `0.2.4` adds `version: "3"` for the [v3 speech contract](../../docs/API.md#external-accounting-v3). `operationEligibility(datasetId, accountId, {operation_family, capability, selection_kind, model_id?})` reads a digest-bound decision. Use `selection_kind: "provider_selected"` only when the actual speech request omits a model selector and the provider may choose it; `not_applicable` requires independent knowledge that no model identity applies. `setAccountPermissions(accountId, {dataset_id, expected_revision, allowed_models, allowed_operations})` is an owner/admin operation. Empty permission lists deny new selection. Existing v1/v2 methods remain version-specific. Telemetry delivery never authorizes repeating a provider call.
