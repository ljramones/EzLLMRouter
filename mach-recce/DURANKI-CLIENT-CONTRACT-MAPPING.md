## Trust and implementation boundary

The JavaScript/Python network clients should serialize and validate their own inputs for developer feedback. They cannot authenticate caller-supplied principal, invent taint or task ownership, authorize a destination, persist dispatch intent, or mark a step accepted. Duranki's server must enforce admission and final dispatch under baseline §5.1–5.4; the orchestrator must own semantic verification and single-winner acceptance under §8. The Phase 1a admission profile allows flagged metadata migration gaps only where baseline §5.1 says so.

No choice of server runtime, LiteLLM conformance, Vega endpoint replacement, or traffic migration is made by this mapping.
