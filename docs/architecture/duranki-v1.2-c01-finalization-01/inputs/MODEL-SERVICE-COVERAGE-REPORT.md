# Mach33 model and AI-service coverage rescan

**Assessment date:** 2026-10-25. **Evidence status:** static source only; no application, provider, database, Docker, or deployed runtime was contacted. The companion inventory records file SHA-256 values and inclusive line ranges. This is a coverage and gap assessment, not an integration approval.

## Findings that change the earlier picture

1. **Embedding and reranking are concrete, separate provider operations.** `lib/voyage.js:18-85` sends batches to Voyage `/embeddings` and candidate passages to `/rerank`. Record indexing and search use document/query embeddings, PostgreSQL pgvector HNSW recall and then rerank (`lib/record-index.js:26-99`); Cristi indexes passages with the same embed wrapper (`lib/cristi-semantic-search.js:70-96`). The wrapper discards any usage fields. The default embedding is `voyage-3` at an assumed 1024 dimensions and the default reranker is `rerank-2`; environment overrides mean deployed values are unknown. Precomputed indexing is its own work, not a charge to each later reader. A substitute embedding model needs a compatible dimension, vector space and index rebuild/validation; rerank substitution needs score/order quality checks.
2. **Speech is several APIs and lifecycles.** Proto voice picks Deepgram `nova-2` when its key is configured, otherwise xAI STT (`lib/proto/voice-body.js:45-111`). Team chat also contains Deepgram, OpenAI transcription and xAI paths (`lib/team-chat/routes.js:2240-2290`), while Relay includes Google Speech `recognize` with `latest_long` (`packages/@agents/relay/body/routes.js:744-766`). TTS branches between xAI and ElevenLabs (`lib/proto/voice-body.js:142-229`). Realtime voice is a stateful xAI WebSocket with PCM16, VAD, transcription, cancel and reconnection (`lib/proto/voice/realtime-body.js:43-105,170-258`). None is safely represented as an ordinary text-token request. Whether transcription is billed separately within realtime and the native audio units/rates remain unknown.
3. **Image paths differ materially.** Attachment image extraction calls an Anthropic vision-capable *multimodal LLM* via the Vega agent Coordinator, returning text and caption (`lib/ingestion/extractors/image.js:11-24`; `lib/ingestion/agents.js:145-169`). Vega screen reading also sends image blocks to Anthropic (`lib/vega-grok-view.js:286-308`). Editorial images use xAI image generation, then download/persist media or return a temporary URL if persistence fails (`lib/vega-grok-image.js:130-182`). Neither is evidence of a separate OCR model or image-editing API. PDF extraction here uses local `pdf-parse` (`lib/ingestion/extractors/pdf.js:3-19`) and is not a paid model call; scanned PDFs can yield little text.
4. **Search can be a model tool or an adjacent service.** Vega and Bud use xAI Responses with `web_search` (`lib/vega-chat.js:6340-6407`; `lib/numerics-tier2/providers/xai-web-search-adapter.js:30-68`; `apps/bud/mcp/web-search-server.js:3-25`). The numerics tier2 adapters also call SerpAPI Google Scholar, Semantic Scholar and arXiv, preserving transport invocations and result observations but not price/usage (`lib/numerics-tier2/providers/*.js`; `lib/numerics-tier2/providers/index.js:215-270`). `searchAcademic` fans out and deduplicates (`lib/epistemic/academic-search.js:341-418`). SerpAPI is marked `PAID_PROVIDER` in source; Semantic Scholar and arXiv are read-only fetch classifications, not proof of zero bill. Klipy GIF search is another adjacent API (`lib/team-chat/gif-search.js:120-139`). Search-result count is not automatically billable unit count.
5. **Labels do not establish an inference class.** The email `classifyEmails` path is Anthropic Messages with a forced tool (`packages/@agents/my-assistant/body/index.js:732-745`); cluster refinement also calls Anthropic (`lib/vega-agents/composers/cluster-classifier.js:112-140`). By contrast `lib/vega-live/classifier.js:1-18` is explicitly pure local logic, and some epistemic “semantic” detectors use Jaccard rules. A registered catalogue item, role name or model-capability label cannot stand in for a transport trace.
6. **Bud has an opaque external execution boundary.** Its optional Grok Build backend launches an external binary and sends ACP `session/prompt`; it logs `turn_completed` input/output/cache-read counts and uses them for session rotation (`apps/bud/index.js:89-120`; `apps/bud/grok-backend.js:735-750,1028-1052,1718-1735,1788-1801`). The external binary and its provider transport were not inspected. Those local counters are not a durable priced attempt ledger or proof that Duranki can enforce a send.

## Duranki fit at inspected HEAD

Duranki HEAD `d990b78c...` has a tested selected provider path for **one exact OpenAI Responses nonstreaming text model**, no tools, no retries/fallbacks, with frozen worker, final guard and trusted sender (`server/src/duranki_server/core.py:201-222,369-380`; `tests/gateway_integration/choice_b_worker.py:143-162`). `Coordinator.capabilities` explicitly disables `realtime_voice`, `binary_multimodal`, `responses_web_search`, streaming, background and provider-managed state. The registry enforces principal/model/grant/purpose/task class and supported request features (`server/src/duranki_server/registry.py:512-527`), but descriptive catalogue capabilities are not execution support. Provider model-list adapters are probes; most are not inference routes (`server/src/duranki_server/provider_adapters.py:23-38`).

DEV-11 adds an immutable **Responses text** implicit-cache contract with one price tier and four exact USD token rates, plus conservative exposure and unknown-cost handling (`server/src/duranki_server/cache_accounting.py:15-70,90-161`; `server/src/duranki_server/personal_campaign.py:189-273`). Its tests and controlled browser record are in `docs/development/dev-11/RESULT.md`. This is reusable architecture—identities, grants, signed work, no-repeat send, reservation, exact decimals, revisions, reporting—not a universal rate parser. The text-only output normalizer expects assistant text/tool calls (`server/src/duranki_server/core.py:583-603`). Audio seconds, characters, image count/quality, search requests, storage and local compute need native units and separate price contracts. Missing usage must remain unknown; a source default of zero in another app is not provider-reported zero.

**Disposition:** MS-01 is an adapter extension for selected nonstreaming chat, and a lifecycle extension for streaming/tool cycles. MS-02/03/04/05/06/08/09 require operation-level request and permission contracts, native usage/price bounds and adapters; media adds artifact handling. MS-07 needs a session/reconnect/cancellation lifecycle before any enforced paid path. MS-10/11/14 are adjacent-service observations until billability and charging scope are reviewed. MS-12 is external-observation-only until trusted transport ownership can be established. MS-13/15 do not need model routes. A generic provider label cannot authorize substitution: output schema, embedding index compatibility, ranking semantics, media format/version, persistent state and quality assessment must be checked per operation.

## Smallest independent development sequence (synthetic only)

1. **Operation/usage ledger foundation (P1).** Add an explicit operation ID to synthetic registration, grant, signed intent and reporting; represent native units with known/absent/null/unknown states, exact price-version references and distinct task/agent/initiator/charging-owner lineage. Prove unique attempt accounting, conservative reservations, duplicate suppression and unknown exposure using a controlled receiver. 2. **Voyage-shaped embedding and rerank fixtures (P1).** Use two synthetic endpoints and a versioned fake index. Exercise document-versus-query role, batch limit, vector dimensions, a separate rerank attempt, failed rerank fallback, and shared indexing allocation held separate from a reader's query. Do not select real Voyage models or rates.
3. **One audio transcription fixture and one multimodal vision fixture (P1).** Audio: two chunks with stable identities, a provider-style duration observation, replay and missing usage. Vision: image input constraints and a text/caption response with provider-style token usage; no actual image bytes retained in the test record. Both must fail closed under the current text route until a reviewed operation contract exists.
4. **Responses web-search accounting fixture (P1/P2).** Synthetic model tokens plus a separate hosted-tool unit and citations; preserve an unknown fee when the tool observation is incomplete. Use the existing xAI adapter shape as source evidence, not as a Duranki-ready endpoint.
5. **Image/TTS artifact and realtime session fixtures (P2/P3).** First prove generated media byte custody and uncertain download outcome; then a WS transcript with cancellation/reconnect and partial usage. Passive ACP observation for Bud may follow, but should not be described as finite spend enforcement.

No real provider, model, price, currency, allowance or request count is selected by these proposals. Commercial importance and request frequency are unknown.

## Coverage and open boundaries

Inspected tracked first-party JavaScript across `apps/`, `lib/`, `packages/` and selected source manifests; compared Duranki Python `server/src/`, frozen `tests/gateway_integration/`, `clients/` validation and DEV-10/11 living records. Searches covered SDK message calls; `fetch`, WebSocket, subprocess/ACP and Google Speech transport; embedding/rerank, STT/TTS, image/vision/PDF, search/vector; and local model/accelerator terms. Selected paths were traced from entry to wrapper to response consumer. The inventory hashes each cited file. Historical `mach-recce/` inputs were read but not treated as current runtime proof.

Excluded intentionally: secret files/values, untracked platform `artifacts/`, databases, deployed config, provider APIs, invoices, generated media, application startup, builds, tests and dependency source. Dynamic plugin/MCP registration, the external Grok Build binary, SDK retry details beyond source-set options, and exact account scope remain unresolved. Dedicated moderation, translation, image edit, video generation/inference, and active local Ollama/vLLM/WebGPU model calls were **not found in the inspected first-party scope**; this is not universal absence. Media video-call transport is not evidence of video-model inference. No external official docs were consulted, so native pricing units are explicitly unresolved where source does not expose them.
