## Out-of-tree guard feasibility and open write gap

The proposed `httpx.AsyncBaseTransport` wrapper is a plausible supported extension: hold a per-request immutable signed context, capture the final request bytes/control fields, recompute authorization, append and `fsync` intent plus directory creation, then delegate once. Use a task-local context token, not one mutable global principal. Every transport invocation must draw from a signed attempt allowance; a new UUID does not grant a retry. Instrument a separate independent receiver; no gateway log can assert delivery on its behalf.

The guard occurs **before** delegation. A pool wait or queued task beneath it can leave a revoked or cancelled attempt authorized but not transmitted. A transport wrapper alone cannot promise a final recheck immediately before the first socket write without verifying a supported lower extension or arranging a cancellation-safe dispatch gate. No vendor patch or monkey-patched internal method is accepted as a supported boundary. The exact SDK/HTTPX/httpcore source and dynamic receiver proof must determine whether this gap can be closed out of tree. If not, DEC-09 must return to the owner for an independent admission/send layer or alternate gateway approach. The current answer is **UNRESOLVED**, not an FDC PASS.

For total timeout, an outer monotonic attempt deadline must encompass pool wait, send and complete response consumption, with finite cancellation/supervisor drain; HTTPX read inactivity timeout alone cannot meet it. The B1 proof retains a five-second post-drain observation horizon and its empirical limit. For retries, default signed allowance is zero. A separately declared nonzero fixture must allocate a new authorized attempt with durable intent before each send. Every negative case requires positive receiver controls before and after, reached-stage evidence and same-allowed-receiver bypass probing.
