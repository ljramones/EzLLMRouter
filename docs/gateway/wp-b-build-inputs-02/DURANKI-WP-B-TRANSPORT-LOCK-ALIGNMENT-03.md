## Proposed proof boundary and DEC-09

The out-of-tree HTTPX `AsyncBaseTransport` wrapper remains a **hypothesis** for freezing final method, URL, headers, body and controls, checking signed attempt/context, and durably recording intent before delegation. A separate lower gate must establish that authorization remains valid immediately before the **first actual network write**, after pool/connect/TLS waits and any cancellation checkpoint. Every enabled redirect, proxy mount, retry, alternate LiteLLM HTTP handler or streaming path must be disabled or brought under the same fresh-attempt authority. HTTPX's supported transport interface is suitable for preparation interception; the matching httpcore trace interface is not an exclusive actual-write gate. The exact OpenAI 2.54.0 and AnyIO 4.15.1 paths must be checked before treating this as release-aligned.

The four retained obligations are: (1) exclusive first-write admission, with durable intent before independent receiver arrival; (2) one total deadline through full response-body consumption; (3) fresh signed attempt and preserved error/context semantics for every retry, redirect or exception; and (4) independent receiver plus socket/egress observation, including positive controls and bounded negative windows. **DEC-09 remains open:** can a supported, out-of-tree wrapper/backend for these exact versions prove an atomic guard-to-write boundary and exclusive route, or is a different admission/send layer required? Static source analysis alone cannot close it. B-01–B-09 remain `NOT_RUN`; WP-B/B1 and WP-C remain `NOT_ISSUED`.
