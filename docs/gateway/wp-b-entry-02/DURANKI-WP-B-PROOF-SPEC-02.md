## Exact experimental seam

Run the real LiteLLM FastAPI `/v1/chat/completions` endpoint (`C:litellm/proxy/proxy_server.py:11940–12016`) with one `Router` deployment whose `litellm_params.model` selects the OpenAI-compatible non-GPT-5 chat branch and whose `api_base` is a loopback synthetic OpenAI-protocol receiver. Pin its synthetic model/version, explicit `stream:false`, tool support, `request_timeout:1s`, no fallback/model alias/automatic Responses conversion, and no real provider credential. `Router` is the internal fixed-deployment dispatcher (`C:litellm/router.py:2779–2807`), distinct from the forbidden `auto_router/*` model feature. The exact config grammar and behavior must be frozen from the selected release and tested at startup before any proof can pass.

An **out-of-tree** startup wrapper around `proxy_server.app` (`C:litellm/proxy/proxy_server.py:1731–1743`) provides synthetic trusted principal/owner and a real ephemeral Ed25519-signed adopted `ExecutionPlan`. It sets a request-scoped context before dispatch and rejects every missing/mismatched plan, unsupported path and user-supplied routing override. A `ContextVar` may carry the verified plan to the transport; B must prove it survives `asyncio.create_task` and cannot leak between concurrent requests (`C:litellm/proxy/common_request_processing.py:2598–2635`). The wrapper is not the FDC; it supplies authority. No vector `SYMBOLIC_NOT_VALIDATED` signature counts as valid.

Before the first request, the out-of-tree starter sets `litellm.aclient_session` (`C:litellm/__init__.py:423–424`) to a custom `httpx.AsyncClient` with **one** `GuardTransport`, no mounts, redirects or proxy, before any OpenAI SDK client is cached. The selected adapter obtains this global session (`C:litellm/llms/openai/common_utils.py:306–330`), gives it to `AsyncOpenAI` (`C:litellm/llms/openai/openai.py:374–447`), transforms the request (`:889–955`; `C:litellm/llms/openai/chat/gpt_transformation.py:476–542`) and invokes `chat.completions.with_raw_response.create` (`openai.py:465–484`). At `GuardTransport.handle_async_request(httpx.Request)`, read/cache the final body once; independently reconstruct expected provider bytes from signed canonical work and the pinned recipe; compare raw bytes plus method, URL, endpoint, model, relevant headers, timeout extension and other material controls. Recheck signature/expiry/revocation/current versions/classification/destination/spend/deadline. Allocate a unique attempt ID, append intent with file `fsync` and directory `fsync` on creation, then delegate **once** to the underlying loopback transport. Guard every invocation, even one caused by SDK retry. No guard event, no send. All exceptions must propagate as a hard failure; observational `log_input_event` swallows exceptions (`C:litellm/integrations/custom_logger.py:533–558`) and is excluded as an enforcement point.

This seam is a defensible **hypothesis**, not a source proof of exclusive transmission. The acquired `openai` and `httpx` dependency source is not closed; verify their exact transport API/retry behavior before execution. `C:litellm/main.py:2648–2690` can select a separate base HTTP handler by environment flag; its `C:litellm/llms/custom_httpx/http_handler.py:831–850,1065–1094` path resends with a new client on connection/protocol errors and would bypass this session guard. Startup must reject that flag, and a receiver/egress negative must prove the branch cannot send in the selected process. A successful pre-call check or receiver silence from a disconnected route is invalid.

## Receiver, intent and observation rules

Use one proposed disposable macOS arm64 VM with network adapter disconnected and only loopback sockets. Its availability, VM control, listener and local socket policy have **not** been checked or authorized. Acquire and verify artifacts in a separate permitted stage before no-egress execution; no host-runtime path is assumed to exist inside the VM. The receiver is an independently implemented OpenAI chat-completions server, with a distinct process and append-only raw synthetic request log. It returns controlled success, tool, error, delayed and connection-close responses. Before **and after** every negative case, an admitted B-01 control must reach it; the receiver's own liveness probe is marked separately and excluded from attempt counts. Log method, loopback address/port/path, request-body bytes/hash, safe material headers, connection ID, response/close and receiver sequence. Disallow every other loopback destination too; a disconnected external NIC alone cannot exclude a bypass to another local listener.

The experimental intent recorder is an append-only, mode-restricted file with sequence, attempt/plan/work/prepared digests, current version IDs and disposition. Acknowledgment follows successful write+`fsync`; newly created file/directory metadata is `fsync`ed. At an injected barrier after acknowledgment and before send, update current policy or cancellation and append a durable no-send disposition if blocked; the original intent remains. Restart and verify the persisted sequence/disposition. A write or `fsync` failure must block send. This is one-host ordering, not production ledger/WAL or distributed 1b recovery. Cross-process timestamps alone do not prove order: record the guard's append acknowledgment sequence and the receiver's corresponding attempt token, and gate release on the acknowledgment. Every actual send consumes a fresh attempt token; a retry must redo FDC and intent.

For an expected negative, record the reached guard stage, explicit rejection reason, absent intent where appropriate, receiver count, socket trace and a **5-second observation window after all gateway tasks drain**, exceeding the proposed one-second attempt timeout. Any delayed send in that window fails; a proof cannot claim absence beyond the observed horizon. Retain positive controls and raw failed results. The independent receiver must see exactly the planned request in positives and zero unauthorized sends in negatives. A schema or front-door failure is a separate assertion, never credit for B-03/B-05 FDC interception.
