# WP-B/B1 pinned gateway proof specification 01

**17 October 2026 · `PROPOSED_FOR_EXPERIMENT` · `NOT_RUN`**

This specifies the first actual LiteLLM boundary experiment against adopted wire `0.2`, projection `duranki-work-v0.2`, profile `initial_1a@1`. It is conditional on DEC-13's missing pinned source and dependency evidence [candidate review](DURANKI-DEC13-GATEWAY-CANDIDATE-01.md). It does not qualify a gateway or reopen DEC-04–08 [A2 adoption](../../contracts/WP-A-A2-ADOPTION-01.md).

## Boundary, actors and invariant

Use one disposable macOS arm64 VM/run for a **Python-only** gateway experiment, an isolated Python environment and package cache, synthetic principal/owner, prompt and policy registry, one approved local deployment, and no real provider key. Acquire and verify all permitted artifacts **before** the VM's execution phase; run gateway and receiver with the VM network adapter disconnected, no default route or external DNS, and loopback as the only socket path. Record VM network configuration, route table, socket connections and a denied off-loopback probe. The ability to create/control this VM and its loopback listener is **not checked** and needs a separate bounded execution permission. A separately implemented loopback receiver speaks the selected adapter's provider protocol and records arrival time, method/path, headers after secret redaction, raw body digest/bytes in the restricted synthetic evidence area, connection count and response identity/usage. A receiver self-check sends a known local probe before negative cases; its probe is excluded from provider-attempt counts. A signed synthetic plan uses a fresh ephemeral **experiment-only** Ed25519 key, whose public key/version is trusted by the experimental gateway. The existing vectors' `SYMBOLIC_NOT_VALIDATED` signature is not used as a runtime pass.

The proposed extension is an out-of-tree gateway module registered through a **pinned-source-confirmed public extension point**. It must own or intercept the final send of the selected real LiteLLM adapter path, compare independently regenerated expected bytes with observed final bytes and destination/endpoint/model/timeout/headers, perform current FDC, synchronously append an intent record, and only then release the send. The adapter and LiteLLM transport must really run. If the pinned release cannot expose that boundary without a fork/vendor edit, stop and report DEC-09 contingency. An earlier callback, schema check, or handwritten provider stand-in is not an FDC proof.

For this local proof, the intent recorder is an append-only file opened with restrictive permissions in the fresh run's evidence directory. Each record includes sequence, attempt ID, plan/prepared digests, current versions, timestamp and cancellation disposition, and is acknowledged only after write **and `fsync` of the file**; creation/rotation additionally `fsync`s the containing directory. Inject write and `fsync` failures and confirm no receiver traffic. Restart the experimental process and compare the durable record with receiver arrivals. This demonstrates one-host ordering only; production replicated WAL/ledger, crash consistency across filesystems and Phase 1b exposure/recovery are separate. Capture a barrier immediately after intent acknowledgment and before send for revocation/cancellation intervention; no unguarded retry may resume past it.

## Concrete proof cases

Each case invokes the future `tests/gateway-proof/driver.py` with `--case <ID>` from the repository root. It records the exact process argv, cwd, environment allowlist, stdout, stderr and exit status of **every** child command, plus receiver/event logs. The driver must assert both gateway result and independent receiver observation. All tests begin with the receiver self-check and reset its per-case attempt log. The case fixture comes from the adopted [vectors](../../contracts/wp-a-03-c01/DURANKI-WP-A-VECTORS-v0.3-CORRECTION-01.json); the named vector is a contract input, not prior runtime evidence.

## Route and control census

Before B-01, derive the actual route table from the selected commit and its startup config. Proposed initial **enabled/tested** route: only non-streaming chat completions for text and supported tools to one fixed loopback deployment. Proposed **blocked with enforcement plus rejection test**: Auto Router, model substitution, load balancing, fallback, alternate endpoint, streaming, Responses/web search, realtime, binary modalities, provider-managed state, background model calls, response cache and unauthenticated/direct proxy ingress. Automatic transport retry is blocked unless B-08 proves per-attempt FDC/intent at the actual retry send. Callback/export telemetry must be allowlisted and content safe. Passthrough/TypeSafe is outside the initial enabled path **with a remaining architecture §4.3 verification obligation**; if the selected gateway exposes an enabled passthrough, B must test it or reject it, including attribution. The source review must replace every proposed block with the exact config switch and send-path enforcement result; no route is assumed blocked from prose alone.

Budget behavior must be checked at admission and again at FDC using current synthetic financial state, with no fallback identity on state-store failure. The experiment's local append recorder and synthetic budget state are scaffolding, not production Nisaba, managed ledger or high availability. No real model, provider, TypeSafe service, production secret, telemetry endpoint or Vega connection is used.
