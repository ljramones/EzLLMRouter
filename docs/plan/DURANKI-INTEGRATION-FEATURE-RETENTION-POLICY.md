# Integration feature retention policy — proposed for owner adoption

**Status: PROPOSED, not approved for live Vega collection.** The adopted architecture's §13 requires derived features to inherit source handling/retention unless an approved feature schema permits longer retention; §18 leaves numeric defaults to confirm. This table defines the local v2 machinery and the decision Larry must make before real T0. No raw content is ingested by this accounting interface.

| Fields or record | Purpose | Classification / source | Retention and expiry | Readers and exporters |
| --- | --- | --- | --- | --- |
| Dataset, attempt, attribution, operation, account ID/state history, usage/cost revisions, outcome, receipt, eligibility answer, snapshot ID/digest/status | Auditable accounting and replay-safe observation delivery | Non-content operational metadata; owner/client terms still apply | Proposed approximately 13 months (maximum 397 days for captured snapshot content); final accounting horizon requires owner confirmation | Authenticated dataset owner/admin and same-owner report principal; ingest principal reads its own receipts/eligibility |
| `task_category`, `operation_category`, `modalities`, `input_size` (unit, value, measured/estimated provenance) | Pre-call grouping and later routing analysis | Allowlisted categorical/numeric fields; inherit source/client restrictions | Default local release: synthetic low-class only, at most 397 days and no later than supplied source cutoff. Real low/internal captured values require an explicit approved policy file and source expiry | Same-owner report/export, authenticated ingest snapshot retrieval; no public export |
| `requested_output_tokens`, `latency_budget_ms`, `required_capabilities`, `agent_version`, `policy_version`, `configuration_version` | Record declared constraints and configuration available at selection | Same feature rule; IDs are not automatically harmless or exempt | Same bounded cutoff; source/availability times retained after content expiry | Same restricted readers/exporters |
| Selected account/model, policy, immutable eligibility answer ID/revision/decision/time/digest | Reconstruct selected action and eligibility evidence | Decision snapshot; no credential value | Snapshot content expires at bounded cutoff; event/accounting identifiers remain under proposed audit horizon | Same-owner report/export; ingest retrieves its own decision snapshot |
| Raw prompt, response, audio, image, video, embedding, free-form metadata, credential, secret-bearing URL | Outside initial accounting purpose | Prohibited in this store | Never collect | None |

`classification` is `low`, `internal` or `confidential`. The current local process stores captured content in the isolated SQLite database and therefore **does not accept real captured content by default**. An owner-supplied `--feature-policy-file` may approve only low/internal classes, with exact `policy_id`, `approved_by:owner.local`, and `max_days_by_class` values from 1 through 397. It must be a local regular file not writable by group/other. The service also requires each real captured snapshot's `source_expires_at` and refuses a later retention cutoff. This mechanism does not itself approve any field, class, duration, client term, encryption or live dataset activation. Confidential and highest-sensitivity captured features remain excluded from this local profile.

At expiry the service deletes snapshot content from the live database on startup and snapshot/report/export access; it preserves the immutable digest, status and accounting records. Restoring an earlier backup into this service triggers the same purge before reads. Operators must separately expire or destroy **offline backups, exported files, queues and caches** containing permitted content; this local software cannot reach copies outside its database. A policy adoption must specify those schedules and permitted recipients. Hashes inherit source-policy review; a digest is retained only as an integrity/absence marker, not asserted to be anonymous.

**Owner decision before real T0:** approve or narrow each retained field and category vocabulary; confirm source/client classification and expiry rules, permitted readers/exporters, low/internal maximum days, backup/export deletion and whether storage protection is sufficient. Do not activate collection or send real feature snapshots until that decision is recorded. Synthetic conformance and the accounting-only interface can be tested now.
