## Causes and changes

The previous Connections editor sent **Try a different key** to Add provider. The database credential service's `replace` method accepted only `connected` records, so a UI-only change could not repair a failed pending registration. The service now validates a replacement candidate for a pending or connected record under the same account ID. A pending result retains a new encrypted candidate and discovery state; it remains editable on failure and can be saved after successful discovery. A connected result promotes only after successful discovery; a failed candidate leaves the selected credential and policy intact. Expected record revisions reject stale submissions, and discovery records the candidate credential version and record revision. Failed and observed pending registrations now survive the startup cleanup that applies only to never-checked pending rows. The editor offers **Change API key**, a masked field, **Validate and save**, and **Cancel** on pending, failed and connected records. A successful pending discovery returns to model selection and Save.

The previous integration-only route used a small external-observation report, while the established DEV-09 `web/usage_costs_view.js` was loaded but its `/operator/v1/usage-costs`, model and principal read endpoints were blocked by the integration-only profile. The recovered implementation began at commit `2fdc3eb04f8ebf9d1e4125b6b985ec5e3cb339aa`; the populated DEV-09 screenshot baseline is in `docs/development/dev-09/screenshots/` at revision `018df8391c25ce326c017bf84eec634704d59c39`. The current `web/usage_costs_view.js` includes later DEV-12 changes at HEAD `b84c5b1`.

Accounting now has DEV-09 style Overview, Providers, Models, Agents, People & teams, Tasks & workflows, and **Native Duranki** subnavigation. The external sections reuse its chart, identity and cost presentation components against the authorized integration v3 report. Filtered summaries, charts, tables, details and CSV/JSON exports use the same report filters; model, person and workflow filters were added to the authorized report contract. Searchable name/ID choices, date controls, UTC shortcuts, exact-value advanced controls and a synthetic/real collection label replace the ordinary exact-ID and manual timestamp entry. Connection scope is selected separately from the Accounting collection. The Native Duranki section renders the original full `usage_costs_view.js` read-only through its original report and registry read endpoints, under the same authenticated operator session.
